## 3 Overall assessment
MINOR ISSUES (SOUND for numbers). Confidence: high for the 7 modules, reports and site; medium for the rest of the claim, because the ML, severity, person and Phase-2 modules were not re-run and the seed check was not completed. Most damaging issue: the "every number regenerates" claim rests on a single clean rerun by the project's own audit, and Phase-1 provenance points to an unreachable commit, so a third party cannot tell which code produced those 123 tables. The one literal prose error found (#1) is small. Bootstrap CIs reproduce bit-identically only under the fixed seed 20240601; robustness to the seed is not tested.

## 4 Recommended corrections
Fix the case_comparisons template literal (use a placeholder or "48 each"); state in the audit doc which tables the 156 covers; record per-module code hashes in sidecars; make deaths fail loudly when matched inputs are missing; add .python-version.
